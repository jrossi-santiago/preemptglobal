# Preempt Global — LinkedIn Content Framework
*Reference doc for the LinkedIn content-writing agent. Text-only, written in one weekly batch, spaced across the week via LinkedIn's native scheduler.*

---

## How this doc fits with the other two

This framework governs **what to write about and how a post is structured** (post type, weekly mix, topic bank). It does not contain tone, vocabulary, or hook-writing rules — those live elsewhere, and this doc defers to them completely:

- **`BRAND_VOICE.md`** — the only source for tone, vocabulary, sentence mechanics, terminology accuracy, and the accurate description of the industry problem Preempt Global solves (Section 4). Section 1 of that doc also covers all business facts (offer, pricing, stats, guarantee) — there is no separate business-facts file. Read this in full before writing any post.
- **`SWIPE_PATTERNS.md`** — the only source for hook mechanics and structural performance data (direct-address hooks, framework+CTA structure, formatting experiments). This framework tells you *which post type to write*; the swipe-patterns file tells you *how to structure the hook and close once you know the type*.

If anything below conflicts with either of those two docs on tone, wording, or hook style, **the brand voice doc and swipe-patterns doc win.** This framework only governs topic selection, post type, and weekly cadence.

## Audience

Preempt Global, targeting construction/construction-ownership and project-delivery clients (owners, owner's reps, GCs, A/E firms).

## Post Types

Every post is one of these 7 types. Each type maps to specific rules in the other two docs — follow the mapping, don't default to generic narrative structure.

- **Conviction** — a belief stated with zero hedging. Filters the audience; unfollows are fine.
  *Voice tie-in:* built on Pillar 2 (us vs. the process) — the belief should target a specific failure mode from Section 4, never a vague industry complaint.

- **Story** — one specific moment with a lesson the reader can steal. Reader sees themselves in it.
  *Structure tie-in:* hook must follow Swipe-Patterns Rule 1 (direct address to the reader's own situation), not first-person discovery. Founder first-person, if used, goes in the body per Rule 2 — never the hook.

- **Midas** — a result first (numbers, outcome), explanation after. Teach through the win, don't flex.
  *Voice tie-in:* pull real figures from Brand Voice Section 1 (e.g., $78,900 avoided, 32 days protected) or a specific finding-level number per Pillar 1 — never a rounded or invented-sounding figure.

- **Doc** — a named framework or system, presented as a shareable reference. Problem it kills, then walkthrough.
  *Structure tie-in:* this is the highest-performing structure in the swipe-pattern data (Rule 3 — named framework + explicit imperative CTA). Default to this type when the topic is teachable as a repeatable method.

- **Hot Take** — a contrarian critique of how the industry does something, backed by receipts, not just opinion.
  *Voice tie-in:* the critique targets the process described in Brand Voice Section 4 (internal-only review, hope, redo-after-the-fact) — never a fictionalized "old way," never a named competitor or trade.

- **Transformation** — before vs. after. Reader identifies with the "before."
  *Hard constraint:* the "before" state must be the exact broken process described in Brand Voice Section 4 (internal review only → sent to build → hope nothing clashes → change order and redo when it does). Do not substitute any other "old way" narrative, including rejected-submittal or version-mismatch scenarios — those were explicitly ruled out.

- **Vulnerability** — a real failure and what it taught you. Rare — only use if it's been 3+ weeks since the last one.
  *Voice tie-in:* still follows every Hard Rule in Brand Voice Section 7 (no em-dashes, accurate terminology, no invented old-way scenarios). Vulnerability doesn't mean loosening the voice, just narrowing the topic to a real setback.

Hook should always fit the type *and* Swipe-Patterns Rule 1 — e.g., Conviction posts open with the stated belief reframed at the reader ("Your bid set has this problem" rather than "I believe..."), Doc posts open by naming the framework and the problem it kills for the reader specifically.

## Weekly Mix (7 posts, fixed default)

- 2× Doc
- 2× Story
- 1× Midas
- 1× Conviction **or** Hot Take (choose based on topic fit that week)
- 1× Transformation

**Exception:** if no Vulnerability post has run in the last 3 weeks (check the content calendar), swap one Story or Transformation slot for a Vulnerability post instead.

Assign each of the 7 posts to a type before writing so the week doesn't skew all-narrative or all-framework — Doc posts (the best-performing structure per the swipe data) should never be skipped in a given week even if the mix is otherwise adjusted.

## Topic Bank

Pull topics from here only — do not invent unrelated topics.

**Documentation & Process:** RFIs (writing them, response-time tracking, common mistakes), change orders (pricing disputes, scope creep, documentation, markup negotiation), submittals (review turnaround, approval bottlenecks, log tracking), document control (version control, addenda distribution, set-of-record disputes)

**Construction Administration:** owner's rep role, site visit reports, punch lists, pay applications (AIA G702/G703, retainage disputes)

**Cost & Schedule:** critical path scheduling (float, look-aheads, delay claims), budget tracking/cost codes, long-lead procurement, value engineering

**Risk & Disputes:** claims (differing site conditions, delay claims, documentation), contracts (AIA documents, indemnification, risk allocation), insurance & bonding basics

**Technology:** BIM coordination/clash detection, AI in document review, construction PM software adoption (Procore, PlanGrid, Autodesk Build), drone site surveys

**Closeout & Quality:** as-builts and O&M manuals, QA/QC processes, warranty tracking

When a topic overlaps directly with Preempt Global's own offer (QA/QC review, clash detection, submittal turnaround), lean on the vocabulary bank in Brand Voice Section 6 ("caught on paper," "independent pass," "hunting, not confirming," "who's checking the seam") rather than generic industry language.

## Post Mechanics

- 165–215 words per post (matches the length band with performance data behind it — see swipe-patterns file).
- No links in the post body — LinkedIn suppresses reach on posts with outbound links. If a post needs a link, note "[link in first comment]" instead.
- Hook: direct address to the reader, never "I found/reviewed X" (Swipe-Patterns Rule 1).
- CTA: always end with a concrete action or a stated principle/opinion — never "DM me if interested" (collapses trust). Doc and Midas posts especially should close with an explicit imperative per Swipe-Patterns Rule 3.
- Sentence rhythm: vary sentence length; avoid dense uniform paragraphs.
- No em-dashes anywhere — use a regular hyphen with spaces, per Brand Voice Section 3.
- Match `BRAND_VOICE.md` exactly on tone, vocabulary, and terminology accuracy (Section 5 — beams are placed, not poured, etc.).

## Engagement Notes (for the human reviewing output, not the writing itself)

- Likes are vanity — saves and comments/DM shares are the real signal per the swipe-patterns data. Doesn't change how a post is written, but don't judge a post's success by like count alone.
- First 60 minutes after posting matters most for reach — reply to comments quickly. Manual task, not something the writing routine handles.

## Deferred (not in scope yet — revisit if cadence increases)

- Carousels, short-form video, infographics — noted as top-performing formats generally, but out of scope while the routine is text-only.
- Daily engagement (commenting on others' posts) — a manual habit, not something this routine does.
- A dedicated business-facts file (`PREEMPT_CONTEXT.md`) — not created separately; Section 1 of `BRAND_VOICE.md` already covers offer, pricing, stats, and guarantee. Revisit only if the business-facts section outgrows the voice doc.
