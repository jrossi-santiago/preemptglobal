!lede A pre-bid document review sounds like a smaller version of a general construction document review — same idea, just done earlier. It isn't quite that simple. Reviewing a set before it goes out to bid comes with a scope shaped by a hard deadline that a general review doesn't have, and a specific complication a lot of owners don't think to ask about until it happens: what occurs to the review when the bid set itself changes mid-bidding, because an addendum gets issued after the first pass is already done.

## What a pre-bid document review covers by default

At its core, a pre-bid review checks the same thing any construction document review checks — whether the disciplines in a set agree with each other on paper, and whether the drawings agree with the specs. What's specific to the pre-bid version is *when* that check happens and what the findings turn into:

- **Full drawing and spec review, across every discipline in the set** — architectural, structural, mechanical, electrical, plumbing, and any specialty consultant sheets, checked against each other rather than read in isolation.
- **A written, severity-ranked findings report** — each conflict tied to a specific sheet, with a documented cost exposure and schedule impact, delivered while there's still time to act on it before bid.
- **Turnaround measured against the bid date, not a general SLA.** A pre-bid review only has value inside the bid window. A review that finishes after the bid date has already passed isn't a discounted version of the service — it's a different service that happened to arrive too late to use.
- **Findings framed as addenda candidates.** Because the set hasn't been priced yet, a conflict caught here gets fixed with a correction issued to every bidder equally — nobody is asking to get paid for a fix that landed before a contract existed.

That last point is the actual reason pre-bid timing matters. [The cost difference between catching a conflict pre-bid and catching the same conflict at IFC](/blog/pre-bid-drawing-review-vs-ifc-timing/) isn't about the conflict being harder to find later — it's that a fix proposed before contracts are signed is a clarification, and the same fix proposed after is a negotiation.

## The part most owners don't think to ask about: addenda issued mid-bidding

Bid periods aren't static. Bidders submit RFIs, the design team answers them, and the owner's team issues addenda to correct or clarify the documents before the bid deadline — on a mid-size project that can mean somewhere in the range of 8 to 12 addenda over the bid window, and a large institutional pursuit can run well past 20, according to industry reporting on addendum tracking during bidding. Every one of those addenda is, in effect, a small revision to the set that was reviewed.

That raises a scope question a pre-bid review quote doesn't always answer up front: is a single review pass a one-time read of the set as it existed on the day it was reviewed, or does it cover the addenda that get issued afterward, as they land?

The honest answer, for a single flat-rate review, is usually the former. A review scoped as one pass on one issued set checks that set — it doesn't automatically extend to documents that don't exist yet. If an addendum introduces a new cross-discipline conflict, or resolves one incorrectly, that addendum is unreviewed unless the engagement specifically includes re-review of later revisions.

## What's typically not included in a standard pre-bid engagement

A handful of things sit outside baseline pre-bid scope on a flat-rate, single-set engagement — not because they're unimportant, but because they're a different scope of work than reading one issued set once:

- **Revision re-review.** Re-checking every bulletin, addendum, or RFI-driven revision against the rest of the set as bidding proceeds, not just the version reviewed on day one.
- **AHJ handling.** Submitting permit, bulletin, or addendum packages directly to the authority having jurisdiction is a separate scope of ongoing coordination, not a byproduct of finding conflicts in the set.
- **A dedicated point of contact.** On a single bid-set review, this rarely changes the outcome. On a portfolio running several bids at once, having one person with standing context across the program is a different, broader service.
- **A cumulative findings tracker.** A running log of resolved versus open items across more than one review pass is a portfolio-level view, not a one-time deliverable tied to a single bid date.
- **Post-award (IFC-stage) review.** A pre-bid review is scoped to the document set going out to bidders. Whatever gets negotiated and incorporated into the issued-for-construction set afterward is a separate document, reviewed separately if at all.

None of these are hidden by design — they're a different scope than "read this set once before it goes to bid," and a firm should say plainly which side of that line its quote falls on before a set changes hands.

## Why the distinction matters more here than on a general review

On a general, non-time-boxed document review, missing a later revision is inconvenient but recoverable — there's no bid date forcing the issue. On a pre-bid engagement, the bid date is fixed. If an addendum introduces a conflict three days before bids are due and nobody re-reviews it, that conflict goes out to every bidder unchecked, and the review that already happened doesn't retroactively cover it. [What's actually in scope for a bid set to be considered ready](/blog/set-ready-for-bid-document-review-checklist/) is a useful checklist for the initial pass — but it's the addenda that follow the initial pass that most often fall through a scope gap nobody named out loud.

> A pre-bid review is only as current as the last document it actually read — and the bid set kept moving after that.

## What to confirm before a set goes out

Before signing a pre-bid review engagement, three questions cover most of the scope ambiguity that shows up later:

1. **Is the turnaround committed in days, checked against the actual bid date** — not a range that might or might not clear it in time?
2. **Does the scope include drawings and specs, or drawings only?** A spec-only or drawings-only review misses an entire category of conflict that only exists between the two documents.
3. **Are addenda issued after the initial pass covered, or is this strictly a one-time read of the set as issued?**

[Choosing a pre-bid drawing review partner](/blog/choosing-a-pre-bid-drawing-review-partner/) covers the broader vetting questions — reviewer background, full-set versus sampled methodology, what the findings report actually looks like — that apply on top of the scope questions above.

## Frequently Asked Questions

### What's included in a standard pre-bid document review?

A full drawing and spec review across every discipline in the set, a written and severity-ranked findings report with cost exposure and schedule impact per item, an NDA before any drawings move, and a turnaround committed against the actual bid date.

### Does a pre-bid review cover addenda issued during the bidding period?

Not by default. A single flat-rate review is typically scoped to one pass on the set as it existed when reviewed. If an addendum is issued afterward, it's unreviewed unless the engagement specifically includes revision re-review — ask this directly before signing.

### Is a pre-bid document review different from a general construction document review?

The underlying check is the same — cross-discipline coordination and spec-versus-drawing consistency — but a pre-bid review is scoped and timed specifically against the bid date, and its findings are meant to become addenda rather than open-ended recommendations.

### What's typically not included in a pre-bid document review?

AHJ permit and addendum submission handling, re-review of later bulletins or addenda, a dedicated single point of contact, a cumulative findings tracker across multiple engagements, and review of the post-award, issued-for-construction set are common add-ons rather than baseline inclusions on a single bid-set engagement.
