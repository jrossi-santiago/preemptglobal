!lede A "set" ready for bid isn't defined by a deadline on the transmittal email. It's defined by a specific, checkable list of things that have to be true about the documents themselves — and on most projects, nobody owns confirming that list before the set goes out. Here's a document review checklist for what "ready" actually means, item by item, from an owner's side of the table.

Most owners never see this distinction drawn explicitly. A set either gets issued on the date the schedule says it should, or it doesn't. Whether it's actually complete — sheet index matching the sheets, specs matching the drawings, every addendum folded in, every discipline checked against every other discipline — is a separate question from whether it's on time, and it's the question that determines what a set actually costs once bids come back and construction starts.

## Why "ready for bid" needs its own definition

A design team hitting a bid date is not the same claim as a design team issuing a complete, internally consistent set. Both can be true at once, but only one of them is what a subcontractor is actually pricing against. When a set goes out with gaps — a spec section that doesn't match the drawn detail, a sheet the index promises but the package doesn't include, a coordination issue between two disciplines nobody checked against each other — those gaps don't disappear. They get priced as risk by every bidder who catches them, or they get missed and show up later as an RFI, a change order, or both.

Industry frameworks exist for exactly this problem. AIA guidance on owner instructions for bidding procedures and the Construction Specifications Institute's own project design team coordination checklist (CSI TD-2-7) both treat "bid-ready" as a defined, checkable state — not a date. The checklist below is the practical version of that same idea, organized around what an owner or their reviewer can actually verify before a set goes to bid.

## 1. The sheet index matches the actual sheets in the package

This is the most basic completeness check and the one most often skipped, because it sounds too simple to be worth doing on a large set. The cover sheet lists every drawing that's supposed to be in the package. On a multi-discipline commercial or industrial set — sometimes several hundred sheets across a dozen disciplines — reconciling that list against what's actually included, one by one, catches dropped sheets and stale index entries that nothing else will surface.

## 2. Every discipline that touches the project is represented

Civil, architectural, structural, mechanical, electrical, plumbing, fire protection, and — depending on the project — low-voltage, landscape, and specialty trade packages all need to be in the set at a level of development consistent with the bid phase. A set that's thorough on architectural and structural but thin on MEP coordination isn't a smaller version of a ready set; it's a set with an entire category of coordination risk left unchecked, concentrated in exactly the disciplines that most often produce cross-trade clashes.

## 3. The specifications match the drawings, section by section

The project manual and the drawings are supposed to describe the same building two different ways — one in prose organized by CSI MasterFormat division, one in plan and section. A spec calling for a clearance, rating, or material the drawn detail doesn't actually accommodate is a contradiction that doesn't show up by reading either document alone. It only surfaces when someone reads both against each other, on purpose, section by section. Whichever version a subcontractor happens to price from is the version that determines whether the bid reflects what the project actually costs to build.

## 4. All addenda and bulletins are fully incorporated — not just issued

Issuing an addendum and incorporating it are two different events. An addendum that changes a duct routing or a wall location is supposed to update every sheet that routing or wall touches, with a matching revision cloud and number. What actually happens under deadline pressure is the triggering sheet gets updated and the downstream sheets that reference the same element don't. A set with unincorporated addenda isn't behind — it's actively inconsistent with itself, and reconciling the addenda log against the actual sheet revisions is a checkable, mechanical step most internal QA/QC processes don't cover.

## 5. No placeholder language survives into the bid set

"By others," "TBD," and "coordinate in field" are normal, honest notations at early design phases. On a set issued for bid, the same notes mean an unresolved decision — and its cost — is being pushed onto whoever discovers it in the field. A subcontractor pricing that scope either prices high to cover the unknown or prices low and change-orders the gap once the field decision gets made. Either way, the number in the bid isn't the number the work actually costs, which defeats the purpose of bidding a defined scope in the first place.

## 6. A cross-discipline coordination pass has actually happened, and it's documented

This is the item underneath all the others. Nothing on a transmittal package inherently confirms that anyone read the full set — every discipline checked against every other discipline, specs checked against details, index checked against transmittal — as one coordinated document before it went out. A QA/QC stamp confirms a firm's internal review happened, which is a different, narrower claim, as we've covered in more detail in [why passing QA/QC doesn't mean a set is coordinated](/blog/qa-qc-passed-doesnt-mean-set-coordinated/). If nothing in the package documents that a coordination pass ran, the safest assumption is that one didn't.

## 7. The revision history is legible and current across the whole set

Every sheet carries an issue block with a date and revision number. On a set that's actually ready, those dates and numbers tell a consistent story — the same bulletin appears with the same revision number on every sheet it touched, and no sheet's issue block is stale relative to the addenda log. A revision history that doesn't line up isn't just messy recordkeeping; it's a sign that at least one sheet in the package may not reflect the most current design intent, which is the exact ambiguity a bid set exists to eliminate.

## What this checklist is actually for

None of these seven items require specialized drafting knowledge to check once you know to look for them. What they require is someone reading the complete set as a single document rather than as a folder of individually-correct sheets — the same read described in more detail in [anatomy of a findings report](/blog/anatomy-of-a-findings-report-third-party-plan-review/), which walks through what that kind of review actually produces. A set can pass every internal QA/QC check firm by firm and still fail several items on this list, because QA/QC and cross-discipline completeness are answering two different questions.

The seven items above overlap in places with the kind of red flags covered in [bid set red flags that mean your documents aren't field-ready](/blog/bid-set-red-flags-document-review-checklist/) — that piece is about the specific symptoms; this one is about the underlying definition of "complete" those symptoms violate. Together they describe the same gap from two directions: what a ready set has to be true of, and what it looks like when one of those things isn't.

A set that satisfies every item on this list isn't guaranteed to be free of conflicts — no document review eliminates every possible issue. What it guarantees is that the conflicts still in the set are the kind that require genuine judgment to catch, not the mechanical, checkable gaps that a document review checklist like this one exists to close before they ever reach a bidder's price.

## Frequently Asked Questions

### What's the difference between a set that's "issued" and a set that's actually "ready for bid"?

Issuing a set means it went out on the date the schedule required. Ready means the documents themselves are internally consistent — sheet index matches the package, specs match the drawings, addenda are fully incorporated, and no discipline was left out of the coordination pass. A set can be issued on time and still not be ready by this definition.

### Does a complete sheet index guarantee the set is coordinated?

No. A complete sheet index confirms every promised sheet is present, which is a necessary but not sufficient condition. Coordination — whether the disciplines on those sheets actually agree with each other — is a separate check that has to be run against the content of the sheets, not just their presence in the package.

### Who is typically responsible for confirming a set is complete before bid?

Often nobody specifically, unless someone is scoped to check the full set against itself rather than each discipline checking its own sheets. That gap is exactly what a cross-discipline document review is built to close — reading the set as one document instead of a stack of individually-correct ones.

### What happens if an incomplete set goes out to bid anyway?

Bidders either price around the ambiguity — usually on the high side, to cover the unknown — or they miss it and price a scope that doesn't match what actually has to get built. Either outcome typically resolves later as an RFI or a change order, at a point in the schedule where the fix costs more than it would have as a redline before bid.

### Is a document review checklist the same thing as a spec review?

No. A spec review checks the project manual against itself and against applicable codes and standards. A document review checklist like this one is broader — it checks the specs against the drawings, the drawings against each other across disciplines, and the whole package against its own index and revision history, which a spec-only review doesn't cover.
